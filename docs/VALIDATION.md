# 驗證範圍與合成案例

[專案指令](PROJECT_INSTRUCTIONS.md)是唯一現行行為來源。本頁供維護者查證驗證範圍，不是學習台帳，也不是使用前必讀內容。所有學員輸入均為合成，不含真人答案或分數。

## 證據層級

| 層級 | 已完成與限制 |
| --- | --- |
| 靜態檢查 | `python -B tests/validate_docs.py` 的5項本地檢查：連結／區塊、模式投影、指定隱私模式、合成答案及diff空白；不需學員安裝Python。模式掃描不能證明零個資或秘密。 |
| 人工合成回歸 | 下列D01–D10為輸入／預期處理的人工契約審查；沒有自動分類器，不稱為模型已逐案通過。 |
| 實際模型互動 | 2026-10-28以三個獨立上下文逐輪執行下述非考試情境；合成學員由導演輸入，教師回覆是實際模型輸出。 |
| 真人成效 | 未驗證真人學習、延後保留、跨領域泛化、心理計量等化或實考預測；完整50題長週期及ChatGPT專案UI未在此次實測。 |

沒有配置CI workflow，不把本地檢查或沒有CI狀態寫成CI通過。上述行為驗證來自同一核心指令版本；公開快照整理未修改核心行為。

## 非考試情境與實際觀察

可自行用這個自編小教材試用一般教學：「只有 P 才 Q，表示 Q 發生必須有 P，不保證 P 就足夠導致 Q。若 P 則 Q，表示有 P 就有 Q，不保證 Q 一定由 P 造成。規則沒有提供的方向不能自行補上。」設定：讀懂日常規則、繁體中文、普通Chat、約10分鐘、不考試或評分。

生成器A只讀指令入口與合成需求；教學者B只讀A產出的自含配置；新上下文C只讀B的交接，沒有其他對話內容。使用既有高階模型，沒有降級。導演依當下題目提供合成對錯回答；這不證明真人學會。

| 真實模型回應步驟 | 觀察 |
| --- | --- |
| 配置與起點 | A產生一般教學指令，沒有強加iPAS／考試題數。B用「只有報名才可領證」出一道診斷並等待。 |
| 診斷與有限補解 | 合成錯答自行補上反方向；B設定一個焦點、成功條件及返回點，依序用通知改寫、違規紀錄判斷取得新證據，均標教學後作答。 |
| 換Chat | 第二輪尚未作答即產生交接，保留已啟動2輪／已完成1輪與待答全文。C恢復同題等待，沒有洩答、重診或重設輪數。 |
| 停止與另約 | C收第二輪錯答後停止，不加第三輪；收到明確另約最多1輪才比較單向規則與明文雙向規則，未加入非核心先備。 |
| 驗證與回主線 | 收到合成正確理由後，C標教學後即時達標、結束新段，回必要／充分名稱主線出一道練習；延後無提示檢核仍待辦。 |

初版曾把「單一答案題多解」壓縮成泛稱「多解」，會誤傷開放任務。修正為交接逐字保留已啟用規則後，實際重新產出交接並核對，新上下文C才使用修正版。獨立審查亦修正成功條件及缺模式規則的明示要求；沒有把初版失敗改寫為成功。最終獨立審查未發現內容／入口／驗收阻斷，但不保證每次模型遵從。

使用者所需入口為單份4,465個Unicode字元；共同核心加一般教學規則為1,656字元。這是含空白及Markdown的字元數，不是token數，也不是品質或成效指標。

## 人工合成回歸：難度與狀態


以下D01–D10為人工合成契約案例，已對照現行共同核心／模考模組審查。一般教學、補強亦不得靠加深來避換皮。

| ID／合成輸入 | 預期處理與本次人工核對 |
| --- | --- |
| D01 範圍內但過載：PCA 概念題要求先手算協方差矩陣、求特徵向量、再推導最佳化與正則化。 | 即使答案唯一且各詞在範圍內，難度拒收。相較上述 Q30 多出矩陣運算與推導鏈；移除非核心操作／提供結果，再審核心判斷。不得用長篇補教補票。 |
| D02 正常負荷的實質新題：微調時某設定使單步參數變動過大、原有表徵被破壞。其他設定固定，應先「降低／提高／保持」學習率？前題只考哪些參數凍結。 | 唯一答案降低；區分凍結範圍與更新幅度，非數字／故事替換。與 Q43 比較：同樣需理解微調更新，無額外微分、數值鏈或框架回憶，閱讀不長於錨點。內容負荷審查可通過，仍非實測難度證明。若可見歷史已有同樣的幅度判斷則重審原創性，不固定放行。 |
| D03 只改數字換皮：舊題給 TP=12、FN=3 求 recall，新題換 TP=18、FN=2，或調換選項／故事。 | 仍只代入 TP/(TP+FN)，拒收，即使正解從 0.8 變成 0.9。原題照搬亦拒收。 |
| D04 同方法、新診斷證據：舊題 D03；新任務已給兩個候選式 TP/(TP+FN)、TP/(TP+FP)，請選出分母只涵蓋實際正例的 recall 式。 | 第一式；方法仍是 recall，但由數值代入改成辨識分母人群，測出先前答對數字也可能未理解的部分。不增數據、計算或推導層，不能因方法相同永久禁用。原創性與負荷不增可通過；此案例未提供相近完整官方題，正式代表性仍待核，不能自動放入正式卷。 |
| D05 程式題不等於計算題：Python 3 `items=["x"]; alias=items; alias.append("y"); print(len(items))`，候選輸出 1／2／錯誤。 | 答案 2，必要能力是共用列表參照與原地修改，並非手算鏈；分類為程式語意，計算負荷低。反例 `print(18/(18+2))` 只是算式包裝，不能充當程式理解涵蓋。分類不等於已完成 iPAS 難度校準。 |
| D06 缺官方證據：只有官方目錄連結、檔名或 OCR 缺圖的程式題，卻要求「已完全校準」。 | 明示未讀範圍，不能宣稱已核對完整題或分布；先補必要來源／改用有據候選。若只接受一般練習須明確區隔、不默認納正式計分。 |
| D07 每 10 題檢查：目前 Chat 完整可見 20 道已完成有效題，前後兩段各 10 題；有程式判斷而無手算題，兩科皆有題；只讀過少量官方錨點。 | 同時檢查最近 10 題及累計 20 題，不把程式件數填成計算件數；概念、計算、語意與多步可重疊。說明正式卷分布未核對，不能捏造比例、宣稱符合分布或強補幾題手算湊額。只調後續候選，交接帶最後檢查至 20 與短摘要。 |
| D08 校準中途生效：合成週期 T，目標 50 有效題；已有已核對完成項，另有原題號待答，要求「導正後繼續」。 | 保存原始作答／計分／有效分母及待答題，不重開、不重算、不自動換題或洩答。換 Chat 仍續 T；若明確要求重出且確認未答，才同號撤換、舊版本不多占一題。狀態不明先釐清。完整可見狀態推演如下。 |
| D09 新穎但更深：一個「比例追加件最少數量」例加入變動分母、不等式與整數界線。 | 原創性可通過但正式難度不能因此通過；缺相近正式負荷就退回。不得改為「所有題最多兩步」。 |
| D10 進階與週期結束：要求另出挑戰；或有效題已到 50。 | 挑戰另列、不混正式題數／分母；達 50 先結算並雙交接，新週期等全新 Chat 開考；不把分數轉成實考預測。 |


狀態保全最小合成前提：T週期預定50有效題，第1、2題按既定規準得1、0，原答／題面／提示可見，第3題完整正文仍待答。導正不改小計1/2或待答；明確未答替換仍同號；若之後第3題答對才成2/3。這是算術／狀態契約，不是真人分數。
